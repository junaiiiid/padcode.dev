Formula language reference

Everything formulas can do, with an example of each: values, names, operators, functions, text with braces, dates, and every error message.

A formula is a short expression that works a value out, like total * (1 + tip) / people. PadCode's formulas are written much like Swift: numbers, text in quotes, names, operators, and functions with their values in brackets. This page covers all of it. For a gentler start, see Formulas.

#The sample data

Every example on this page, and on Formula functions, uses these variables. Picture them in Data & Logic, with these starting values:

NameTypeValue

peopleWhole Number3

nicknameTextempty: nothing typed yet
qtyTextText3, typed into a Text Field (so it's text, not a number)
couponAnythingnull: no value at all

tasksList of Recordsthree tasks, each with a title and a True / False done: Call Sam (done), Buy milk (not done), Pay rent (not done)

#How to read the results

The Result column writes each answer the way you'd write that value in a formula, so you can tell its kind:

  • Numbers as they print: 4, 3.5, -2. A whole number never shows .0.
  • Text in double quotes, so you can see spaces and tell "5" from 5. In your app, text shows without the quotes.
  • true, false and null as they are.
  • Lists in square brackets: [70, 82]. In text, a list prints as its items with commas between them.
  • A record the way it prints in text: {"city":"London"}.
  • Error: and the message, when the formula can't give an answer.

Money, percentages, dates and times depend on the iPad's language, region and time zone. On this page they're shown for an iPad set to English (US), in New York time. In late October 2026, New York is 4 hours behind UTC; from November 1 it's 5 hours behind.

#Values

Values are what formulas work with. You can write numbers, text, true and false, null and lists straight into a formula. Records come from your variables, list items and APIs.

#Numbers

Write digits, with a dot for decimals: 12, 3.5, 0.25. Put a minus in front for a negative number. Any number can have decimals, so 7 / 2 is 3.5, and a whole number prints without a dot: 1.0 prints as 1.

FormulaResult
4242
3.503.5
1.01
-7-7
7 / 23.5
0.1 + 0.20.30000000000000004
power(10, 16)1e+16
.5Error: This formula can't be read: unexpected '.'.
+5Error: This formula can't be read: unexpected '+'.
1,000Error: This formula can't be read: unexpected ','.
1e3Error: This formula can't be read: unexpected 'e3'.
  • Write 0.5, not .5, and leave out thousands separators and a leading +.
  • Some decimals can't be stored exactly, so 0.1 + 0.2 prints a long tail. Use round(x, 2) to compare or keep a tidy number, and fixed, currency or percent to show one.
  • Numbers of a million billion (1,000,000,000,000,000) or more print differently: power(10, 15) gives 1000000000000000.0, and bigger ones print like 1e+16.

#Text

Put text in straight quotes, single or double: 'Hello' or "Hello". To put a quote inside, use the other kind around it, or type a backslash before it. A backslash keeps the next character as it is, so there are no codes like \n for a new line: \n is the letter n.

FormulaResult

Curly quotes (‘ ’ and “ ”) aren't quotes to a formula: use the straight ones, ' and ".

#True, false and null

true and false are the two answers a condition gives. null means no value at all: a variable of type Anything that's empty, a field a record doesn't have, or an API value that hasn't loaded. Empty text isn't null: it's text with nothing in it.

#Records

A record holds named fields, like user's name and age. Formulas read records and their fields, but can't write a new one: braces in a formula are an error. Make records with variables of type Record, let an API or a list give them to you, or read them from JSON text with parseJSON. keys and values list a record's fields.

FormulaResult
user.address{"city":"London"}
{city: 'Paris'}Error: This formula can't be read: can't read '{city: 'Pari'.

The error shows up to 12 characters of what it couldn't read.

#Names

A name reads a value: one of your variables, or one of the special names below. Names start with a letter or _, then use letters, numbers and _. They match exactly, capital letters included.

FormulaResult
total120
TotalError: There's nothing called Total. Check the spelling.
totl * 2Error: There's nothing called totl. Check the spelling.

true, false and null always mean those values, so a variable with one of those names can't be read by a formula.

#Reading inside a value

Add .field to read a record's field, and [number] to read a list's item. The first item is [0]. You can also read a field by its name in quotes, ['field'], which works for any field name, even one with spaces. Mix them as deep as you need. Anything inside the square brackets can be a formula.

FormulaResult
user.name"Ada"
user.address.city"London"
user['name']"Ada"
scores[0]70
scores[people - 2]95
tasks[1].title"Buy milk"
tasks[0]['done']true

A field that isn't there gives null, and so does an item past either end of the list. So does reading anything from null, however deep: if coupon is null, coupon.code is null too. That's why ?? works well after a path: user.phone ?? 'No phone'.

FormulaResult
user.phonenull
user.address.zip.codenull
scores[10]null
scores[-1]null
scores[1.5]null
coupon.codenull
tasks.titleError: Can't read .title of a list.
name.countError: Can't read .count of text.
scores['0']Error: Can't read [0] of a list.
user[0]Error: Can't read [0] of an object.
scores.0Error: This formula can't be read: expected a name after '.'.
  • A dot only reads a record's field. To get a field from every item of a list, use map(tasks, it.title).
  • Text and lists have no fields: use functions instead, like count(name).
  • A list's item number must be a whole number, and a record's field name must be text. Messages call a record "an object".

#Special names

Besides your variables, formulas know these names. params and theme exist everywhere; the others only in some places.

NameWhat it isWhere it exists
paramsThe values a screen was opened with: its Screen inputs, like params.id. Inside a reusable action's steps, the inputs that action was run with.On every screen and in every step. An input the screen doesn't have gives null.
itemThe current item.In the views inside a Repeater or a Tree, and in the steps those views run.
itEach item of a list, in turn.Inside filter, find, map, sort, any and all. In the steps of Repeat for Each. In Update in List's Where and With, and Remove from List's Where.
errorWhat went wrong: error.message says it in words. When a Call API got an error answer, error.status is its status code and error.body the server's answer.In a Try's Catch steps.
eventWhat a trigger hands its steps. When a Value Changes: event.oldValue and event.newValue. When Hovered: true as the pointer arrives, false as it leaves. When Dragging Starts or Stops: true as the knob is grabbed, false as it's let go. When Apple Pencil Is Squeezed: event.phase, which is 'began', 'changed' or 'ended'. A Location Button's steps: event.latitude, event.longitude and event.accuracy (in meters).In the steps of those triggers.

Outside its place, one of these names gives "There's nothing called …" when the formula runs. Inside filter, find, map, sort, any and all, it means that function's item, even inside Repeat for Each's steps, and inside a map within a map, it is the inner item.

A variable with one of these names gets in the way: a variable called params, item or theme hides the special name, and it, error, event and pasted hide a variable with their name. Give your variables other names.

Note

The Formula sheet and the notes under condition boxes work formulas out before anything runs, so they don't know these values yet. In the Formula sheet opened from inside the steps that have them, it and error are null. Elsewhere in the editor, item, it, error, event and pasted show "There's nothing called …", even though they work when the app runs. Issues never counts the seven special names as missing.

#What counts as true

Conditions, !, &&, || and ? : accept any value. false, null, 0, empty text and an empty list count as false. Everything else counts as true, including the text 'false', the text '0', a space, and a record with no fields.

FormulaResult

!0true
!'false'false

&&, || and ! always give true or false, never one of the values, so nickname || name is true, not "Sam". To pick a value, use ? : or ??.

#Which part is worked out first

When a formula has several operators, the ones higher in this table are worked out first. Operators on the same row go left to right, except the ones in front of a value and ? :, which group from the right. Brackets ( ) always go first: add them whenever you're not sure.

Two of these catch people out:

  • ?? comes after the comparisons, so user.age ?? 0 > 50 means user.age ?? (0 > 50). Put the fallback in brackets: (user.age ?? 0) > 50.
  • ? : comes last, so everything before the ? is the condition. In 'Status: ' + isMember ? 'member' : 'guest', the condition is the text "Status: true". Put the choice in brackets.

#Functions

A function does a job on the values you give it: write its name, then the values in brackets, separated by commas: round(total / 7, 2). Function names match exactly, capital letters included. Functions go inside each other, and the inner one is worked out first.

  • Some values can be left out: on Formula functions, they end in ?, like round(number, places?).
  • min and max take as many numbers as you like, or one list.
  • filter, find, map, sort, any and all work out their second value once for each item of the list, with it as that item: filter(tasks, !it.done). A function inside, like contains, can use it too.
FormulaResult
round(total / 7, 2)17.14
round(total / 7)17

round(1, 2, 3)Error: round(number, places?) can't take 3 arguments.
now(1)Error: now() can't take 1 argument.
round(qtyText)Error: round needs a number, not text.

Values a function reads as text take anything and use it as it prints, so uppercase(5) is fine. Values it reads as numbers must be numbers. Every function, with what it takes and examples, is on Formula functions.

#Dates and times

Formulas keep dates as text in the ISO 8601 form: '2026-10-28T14:30:00Z' is 2:30 PM on October 28, 2026, in UTC (the Z). A Date & Time variable and a Date Picker store dates this way.

The date functions read:

  • A date and time in UTC, ending in Z: '2026-10-28T14:30:00Z'. Fractions of a second are fine, and dropped.
  • A date and time with an offset from UTC, like '2026-10-28T16:30:00+02:00'.
  • A day on its own: '2026-10-28' means midnight at the start of that day in the iPad's time zone.

now(), today(), date(…), addDays, addMonths, addMinutes and startOf give back a date and time in UTC, ending in Z, to the second. date(…) also reads a number of seconds since 1970, as many web APIs send dates. formatDate turns one into words for people, in the iPad's language and time zone.

  • Comparing dates. <, > and == compare dates as text, which puts them in time order when they're written the same way. To compare dates written differently, pass both through date(…) first.
  • Time zones. A date in UTC can fall on another day where the iPad is: 2 AM UTC on October 28 is still October 27 in New York. formatDate and daysBetween use the iPad's time zone, and so do today() and plain days like '2026-10-28'.
  • Days and minutes. addDays keeps the time on the iPad's clock, so across a change to or from daylight saving time, the UTC time moves by an hour: in New York, a week after 10:30 AM on October 28 is 10:30 AM on November 4, which is 15:30 UTC. addMinutes always adds exact minutes.
  • In text, a date prints as it's stored. Use {formatDate(startDate)} to show it for people.

Date functions: now, today, date, timestamp, addDays, addMonths, addMinutes, startOf, daysBetween and the other …Between functions, the parts of a date (hour, minute, second, day, month, year, weekday), formatDate and formatDuration. sort puts dates in time order when they're written the same way.

When a formula can't give an answer, you see one of these messages. In the messages, "an object" is a record.

#What formulas can't do

A formula works out one value from others. It can't change anything, so some jobs belong to actions instead:

  • No assignment. total = 5 is an error. To change a variable, use a Set Value step.
  • No loops. Use filter, map, find, sort, sum and count on a list, or a Repeat for Each step to run steps for each item.
  • No functions of your own, and no names of your own inside a formula. Put steps you reuse in a reusable action, and keep in-between values in variables.
  • No new records. {…} in a formula is an error. parseJSON('{"a": 1}') reads one from text.
  • No methods. name.count and name.uppercased() don't work: use count(name) and uppercase(name).

#If you know Swift

Formulas look like Swift expressions, with a few differences:

  • Text can use single or double quotes, and + joins text with anything: 'Total: ' + total.
  • There's one kind of number. 7 / 2 is 3.5, and % works with decimals.
  • There's no string interpolation inside a formula: join with +, or use braces in text.
  • Optional chaining is built in and there's no ?.: user.address.city is null when any part is missing.
  • ?? is looser than comparisons, unlike Swift: a ?? 0 > 5 means a ?? (0 > 5).
  • !, &&, || and conditions take any value and use what counts as true.
  • Comparisons don't chain: 1 < 2 < 3 compares true with 3, which is an error.
  • No let, closures, methods, or ===. Functions are free-standing and lowercase-first, like uppercase(name): slice(name, 0, 2), not name.prefix(2), and reverse(scores), not scores.reversed().
  • Angles are in degrees, not radians: sin(90) is 1.
